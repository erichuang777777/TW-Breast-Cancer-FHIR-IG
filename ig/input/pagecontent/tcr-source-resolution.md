# 來源解析與摘錄原則

{% include disclaimer.md %}

同一個臨床概念常有多份文件描述，而且互相不一致。癌登碼冊對這件事有明文規定，
但**每個欄位的規則不一樣**，所以不能寫一個通用的合併函式。

實作：`tcr_workbench/resolution_rules.py`（乳癌 SSF1–10，每條附碼冊頁碼）、
`tcr_workbench/demo_er.py`（端到端示範）。

## 一、「不同來源互相補充」的三種意思

| | 情況 | 可否自動 |
|---|---|---|
| 填補缺漏 | A 沒有、B 有 | 可以，碼冊本身就規定來源優先序 |
| 提高精度 | A「ER 陽性」、B「ER 70% 強染」，B ⊃ A | 可以，無矛盾 |
| 衝突仲裁 | A 70%、B 30% | **不是互補**。碼冊有規則就照規則並記錄理由；沒有規則就人工判斷 |

## 二、規則形狀因欄位而異

| 欄位 | 碼冊規則 | 形狀 |
|---|---|---|
| SSF1 ER | 多顆腫瘤取**反應比例**最高 | 取極值（值） |
| SSF6 Nottingham | 多顆腫瘤取 **BR 分數**最高 | 取極值（分數） |
| SSF9 LVI | **任一份**原發部位病理報告有 LVI 即 010 | 布林 OR |
| SSF3 前導療效 | 除 pCR 外，**臨床醫師綜合判斷**優先於病理報告 | 來源優先序反轉 |
| SSF7 HER2 | FISH > CISH > IHC；IHC 2+ 不可直接編 102 | 檢測方法優先序 |
| 頭頸 SSF1 | 同區域：病理 > 手術 > 影像；**不同區域取最大徑** | 條件式切換 |
| 區域淋巴結侵犯數 | 同一 lymph node chain **不可加總**，不同 chain **可加總** | 分組後聚合 |

以下四句在 SSF1／SSF2／SSF6／SSF10 幾乎逐字重複，因此抽為共用步驟：
侵襲癌優先於原位癌、原發優先於轉移、申報醫院優先於外院、
單顆腫瘤多份標本取手術切除最大體積者。

## 三、時間脈絡不是來源

治療前與前導性治療後的 ER 是**兩個事實**，不是同一事實的兩個來源。癌登用專屬代碼
表達這件事：

| 代碼 | 意義 |
|---|---|
| `111` / `121` | 僅有前導性治療後的數值（陽性／陰性） |
| `888` | 治療前陰性、治療後轉為陽性 |

若在事實層把兩者合併成「這個病人的 ER」，這三個代碼就永遠編不出來。

## 四、端到端示範（ER）

五份互相矛盾的報告：

| 來源 | 值 | 標本／部位 |
|---|---|---|
| 病理報告（本院切除，22mm） | 70%，強染 | 侵襲癌／原發 |
| 病理報告（淋巴結切片） | 30% | 侵襲癌／轉移 |
| 病理報告（同一切除標本） | 15% | 原位癌／原發 |
| 外院 core biopsy | 8% | 侵襲癌／原發 |
| 既有 QBC 申報值 | 70% | — |

規則解析後：

```
→ 採用：ER 70%、強染、侵襲癌、原發、治療前、手術切除、22mm
  · 侵襲癌及原位癌皆有檢測時，優先摘錄侵襲癌之數值
  · 同時具有原發部位和轉移部位病理報告時，以原發部位之數值為編碼依據
  · 本欄位資料以申報醫院為主，若申報醫院無資料方可參考外院
  ✗ 既有申報值僅供對照，證據等級低於原始文件，不得覆蓋病理報告
  ✗ 原發部位同時有侵襲癌檢測值，原位癌數值不採用
  ✗ 原發部位已有檢測值，轉移部位數值不採用
  ✗ 申報醫院已有資料，外院資料不採用

癌症登記 SSF1 = S70      QBC D014 = 1、D015 = 70
```

**落選的觀察會保留並附理由**，複核者看得到「為什麼是 70% 不是 30%」，
不必重讀報告。

## 五、為什麼不做 Task 之間的轉換

| 事實 | 癌登合法碼 | 從 QBC 推得出 | 推不出 |
|---|---|---|---|
| ER | 408 | 103（25%） | 305 |
| PR | 408 | 103（25%） | 305 |
| HER2 | 42 | 13（31%） | 29 |
| Ki-67 | 114 | 102（90%） | 12 |

ER 推不出的 305 個碼中有 300 個是字母碼（`S70` 強染 70%、`I45` 中染 45%…），
因為 QBC 沒有「染色強度」欄位。其他落差：QBC 臨床 T 只有 T0/Tis/T1–T4/Tx，
沒有次分類；QBC 的術前腋下淋巴檢驗是三個布林，癌登要的是顆數。

方向是不對稱的：**癌登 → QBC 幾乎都推得出（降維），QBC → 癌登 會捏造精度**。

值得做的「Task 之間」工作只有三種：

1. **一致性檢查**：兩份申報都產生後互相比對，矛盾即代表抽取有錯 → 進人工佇列
2. **歷史回填**：只對推得出的欄位，且 Provenance 標記為 derived、需複核
3. **審核預填**：把既有申報值當提示顯示，但要人確認
