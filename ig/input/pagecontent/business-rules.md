# QBC 業務規則

{% include disclaimer.md %}

本草案的規則來源是工作區提供的「QBC 乳癌照護品質提升方案 XML 上傳 11507 定版」主表。機器可讀版本保存原始欄名、必要性、格式與規則文字，以及來源檔 SHA-256。

## 已機器化規則

- 115 個合法欄位及最大長度
- Big5 可編碼性
- 真實 `YYYYMMDD` 日期、整數、兩位小數與數值範圍
- 單選及多選 ValueSet、半形逗號與重複碼
- `DIAG_TYPE` 的區段適用性
- `DIAG_TYPE=3` 時 `D058–D085` 復發區段必填；D069 等具有明確個別條件的欄位，以個別條件優先（例如 D069 僅在 D068 包含 13 時必填）
- 女性停經資訊與條件必填
- T/N/M 完整性、Stage 計算及一致性
- 遠端轉移／復發「其他」說明
- 腋下檢驗互斥、ER／PR／HER2／Ki-67 相依欄位
- 淋巴結陽性數不大於總數
- 治療順序、治療類型相依欄位及日期順序
- 追蹤、轉出、結案及死亡條件
- AI 候選與衝突資料的人工核准閘門

## Care Plan JSON 的收案分類（專案決議）

網頁欄位 `ddlReason=初診斷或初次治療` 不等於 QBC `DIAG_TYPE=2`，也不得在缺值時預設為 2。由 Cancer Care Plan JSON 投影至 QBC 檢查資料時，採下列順序規則：

- 有手術，且手術早於抗癌治療，或只有手術：`DIAG_TYPE=1`。
- 抗癌治療早於手術：`DIAG_TYPE=2`。
- 只有抗癌治療、沒有手術，且臨床或病理 M 為 `M1`：`DIAG_TYPE=3`。
- 治療項目標為「前導輔助性癌症治療」：`DIAG_TYPE=2`。
- 沒有手術項目，但治療標為「輔助性癌症治療」：視為手術已在前，`DIAG_TYPE=1`。
- 只有抗癌治療、M0、有臨床 T／N 且沒有病理 TNM：視為尚未手術的新輔助治療，`DIAG_TYPE=2`。
- 治療計畫沒有任何已填治療項目時，標為 `source-incomplete`，不得混入一般待審閱或預設類別。
- 其他仍有資料但規則不足的組合才標為待審閱。

此規則是本草案的機構／專案決議，不宣稱為健保署官方通則。每次推導均須保存治療順序、M 分期及來源路徑的 Provenance。

## 規則識別

每項問題都包含穩定的 rule ID，例如 `QBC-D042-LE-D043`。可由工作臺 API、CLI JSON 或 audit 檔取得。完整欄位表與 rule coverage 位於發布原始碼的 `outputs/qbc_conformance/`。

## 治理界線

官方文字若有疑義或範例與主表衝突，本草案採主表規則並保留原文，不自行改寫為「官方解釋」。新增的安全規則會明確標為 local safety rule，仍須 QBC 業務負責人簽核。
