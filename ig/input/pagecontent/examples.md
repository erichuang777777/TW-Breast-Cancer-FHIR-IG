# 合成範例／Synthetic Examples

> **Every person, identifier, date, organization, result, and treatment on this page is completely synthetic and represents no real patient. These examples are for Profile, mapping, and exchange validation only. They must not be used for clinical decisions or official submission.**

## 範例設計／Example design

範例分成兩層，刻意沿用相同的合成情境：

1. **乳癌共同層**保存原子臨床資料與可重用的乳癌事實。
2. **QBC／P4P Task 層**示範從已審核資料投影成申報欄位、Provenance 與 Submission Bundle。

The examples use two layers of the same synthetic scenario:

1. The **shared breast cancer layer** preserves atomic clinical inputs and reusable facts.
2. The **QBC/P4P task layer** demonstrates projection into reviewed reporting fields, Provenance, and a submission Bundle.

```text
合成病理／檢驗／超音波資料
Synthetic pathology / laboratory / ultrasound data
        ↓
乳癌共同 Profiles 與臨床事實
Shared breast cancer Profiles and clinical facts
        ↓
合成診療流程與人工審核
Synthetic care workflow and human review
        ↓
QBC Observations + Provenance + Submission Bundle
```

## 完整乳癌情境／Complete breast cancer scenario

[Completely Synthetic Breast Cancer Scenario Bundle](Bundle-breast-cancer-synthetic-scenario.html) 將下列資源放在同一個可驗證的 collection Bundle 中：

- 合成 Patient 與乳癌 Condition。
- 合成病理 Specimen、腫瘤標記 Observation 與病理 DiagnosticReport。
- 合成檢驗與超音波 DiagnosticReport。
- 合成分期結構、治療 Procedure、MedicationRequest 與 EpisodeOfCare。

The bundle links a synthetic Patient and breast cancer Condition to synthetic pathology, laboratory, ultrasound, stage, treatment, medication-request, and episode-of-care records. Values intentionally demonstrate structure and lineage rather than clinical realism.

## QBC／P4P Task 範例／Task example

[Completely Synthetic QBC Submission Bundle](Bundle-qbc-submission-example.html) 示範 Task 層的最小交換集合：

- `QBCPatient`：完全合成的個案識別與基本資料。
- `QBCRawDataItemObservation`：經審核後保存的 QBC 分期原始值。
- `QBCProvenance`：資料來源、產生方式與人工審核軌跡。

The QBC bundle is a FHIR exchange and audit representation. It is not the NHIA VPN upload format; validated Big5 XML remains the Task output.

## 正向與反向測試／Positive and negative tests

Repository 另提供三種 `DIAG_TYPE` 的 golden XML／audit 組合，以及三種必須拒絕的負向案例：無效日期、缺少「其他」說明、治療結束早於開始。測試包由 `scripts/build_qbc_test_pack.py` 產生，manifest 明確宣告所有案例均為完全合成。

The repository also contains golden XML/audit pairs for all three `DIAG_TYPE` values and negative cases that must be rejected: an invalid date, a missing “other” description, and treatment ending before it starts. The pack is generated by `scripts/build_qbc_test_pack.py`, and its manifest explicitly declares every case fully synthetic.

## 公開範例規則／Rules for public examples

- 不得複製、變形或去識別化真實病歷作為公開範例。
- 合成身分證、病歷號、機構代碼與姓名必須採固定測試值，並通過 PHI gate。
- 每個 FSH example 的 Title 或 Description 必須標示 `Synthetic`／`合成`。
- 新增範例後必須通過 pytest、SUSHI、IG Publisher QA 與 `scripts/check_no_phi.py`。
- Dates and clinical combinations are test fixtures, not treatment recommendations.
